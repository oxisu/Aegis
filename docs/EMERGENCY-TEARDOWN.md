# 紧急拆除手册

> **网络断了，先看这一节。**
>
> 最短路径只有两步：
>
> ```text
> 1. 开一个【管理员】终端
> 2. aegisctl rollback --token-file .aegis-run/ipc.token
> ```
>
> **本机 IPC 不走网卡**，所以"网断了"不影响它工作。
> 命名管道走的是内核的 NPFS，压根不经过 IP 栈——WFP 的规则管不到它。
> 只要 `aegisd` 进程还活着，这条命令就一定能送到。

---

## 0. 如果你只是跑了演练（`tools/cage-drill.sh`）

演练**自己会恢复**，不需要你做任何事。四层兜底，任何一层生效网络就回来：

| 层 | 手段 | 谁触发 | 上界 |
|---|---|---|---|
| 0 | 10 秒倒计时，规则自动撤销 | `aegisd` 自己 | 10 s |
| 1 | 脚本退出时 `kill aegisd` | 脚本 `trap` | 脚本一结束 |
| 2 | `aegisd --serve-secs 45` 到点自己退出 | 时间 | **45 s（硬上界）** |
| 3 | `bash tools/aegis-restore.sh` | 你 | 一条命令 |
| 4 | 手动（下面 §0.1） | 你 | — |

**第 2 层是真正的安全网**：即使脚本被杀、终端被关、机器卡住，
45 秒后 `aegisd` 一定退出，动态会话随之清空。
也就是说**最坏情况有硬上界，不需要你在场**。

演练的日志在 `.aegis-run/drill-<时间>.log`，守护进程输出在同目录的
`drill-daemon.log`。要复盘看这两个。

### 0.1 脚本也不行时的手动重置

按顺序做，通了就停：

1. **结束 `aegisd` 进程**（这条一定有效）
   任务管理器 → 详细信息 → `aegisd.exe` → 结束任务。
   它的所有规则都在**动态会话**里，进程一死内核就清空。
2. **确认没有残留**
   ```powershell
   netsh wfp show filters > C:\wfp-filters.txt
   Select-String -Path C:\wfp-filters.txt -Pattern "aegis-"
   ```
   有输出就说明还有规则（会话还没散，等几秒再看）。
3. **重启**。本版**不装** Boot 层（引导时间）规则——`preflight` 见到
   `Tier::Boot` 就直接拒绝下发——所以重启之后网络一定是干净的。

## 0.2 三条路，按推荐顺序（一般情况）

| 顺序 | 手段 | 什么时候用 | 会不会丢规则以外的东西 |
|---|---|---|---|
| 1 | `aegisctl rollback` | `aegisd` 还活着 | 不会 |
| 2 | 结束 `aegisd` 进程 | 命令连不上 / 守护进程卡死 | 不会 |
| 3 | 重启 | 上面两条都不行 | 会（未保存的工作） |

**不要**一上来就重启。第 1 条能留下完整的事发现场（审计日志、票据状态），
重启会把现场抹掉，事后就查不出是哪条规则装错了。

---

## 1. 第一条路：`aegisctl rollback`

### 1.1 前置条件

- 一个**管理员**终端（不是"管理员账户登录的普通终端"——要真的提权）。
  `aegisctl` 的危险命令要求本进程 `TokenIsElevated`，否则服务端会拒绝并返回
  退出码 `8`。
- `aegisd` 进程还在跑。

### 1.2 执行

```text
aegisctl rollback --token-file .aegis-run/ipc.token
```

预期输出（**成功**）：

```text
7. → 请求 rollback
8. ← 已标记拆除 10 条，看门狗 200 毫秒内执行
```

如果这批规则**已经被 `confirm` 过**，输出会变成：

```text
8. ← 已请求**紧急强拆** 10 条已确认规则，看门狗 200 毫秒内执行
```

两条都是成功。`rollback` 能撤掉**已确认**的规则，这是刻意的——
笼子装错了的时候，"一条命令能救回来"和"必须重启"是两种完全不同的事故等级。

### 1.3 看结果

守护进程那边会打印：

```text
  [IPC] 倒计时结束或收到拆除指令：已撤销 10 条规则
```

然后立刻试一下网络。撤销会在**收到命令后 200 毫秒内**执行（看门狗巡检周期）。

### 1.4 退出码

| 码 | 含义 | 怎么办 |
|---|---|---|
| 0 | 成功 | 试网络 |
| 3 | 连不上管道 | `aegisd` 不在了 → 走第 2 条路（其实规则多半已经随进程没了） |
| 5 | 鉴权失败 | token 文件不对/过期，确认 `--token-file` 路径 |
| 8 | 服务端拒绝 | 通常是**没提权**；换管理员终端重试 |

## 2. 第二条路：结束 `aegisd` 进程

`aegisd` 的所有规则都开在 **动态会话**（`FWPM_SESSION_FLAG_DYNAMIC`）里。
进程一结束——不管是正常退出、被杀、还是崩溃——内核会**自动清空**这次会话装的
全部规则。

```powershell
# 看一眼在不在
Get-Process aegisd -ErrorAction SilentlyContinue

# 结束它
Stop-Process -Name aegisd -Force
```

或者在任务管理器里结束 `aegisd.exe`。

### 为什么这条一定有效

动态会话的清理是**内核**做的，不依赖进程里任何清理代码。
这条属性是刻意选的：崩溃路径上没有机会执行清理代码，
依赖"记得在退出前清理"就等于在崩的时候留下一个 fail-open 的窗口。

### 副作用

规则全部消失（这正是我们要的）。**审计日志留着**，可以事后复盘。

---

## 3. 第三条路：重启

重启一定清空动态会话。

⚠ **本版不会装 Boot 层（引导时间）规则**，所以重启之后网络一定是干净的。
这是被代码强制的：`aegis-wfp::preflight` 见到计划里有 `Tier::Boot` 规则就
直接拒绝下发（`RefuseReason::BootRulesPresent`）。

> 如果哪天启用了 Boot 背板，"重启能救回来"这条就不再成立了。
> 那一版必须把"如何在不开机的情况下清掉持久化对象"写进本手册，否则不许上线。

## 4. 为什么"没有网络"不影响拆除

拆一次要跨过的东西：

```text
aegisctl  ──命名管道 \\.\pipe\aegis──▶  aegisd  ──WFP 动态会话──▶  内核
           （本机 IPC，不经 IP 栈）        （本机调用）
```

整条路径**没有一跳需要经过被我们拦掉的网卡**。命名管道在内核的 NPFS 上，
`FwpmFilterDeleteById0` 是引擎的本地调用。所以即便默认拒绝把
所有出站流量都挡了，拆除命令照样能到。

反过来这也意味着：**别指望"断网"能阻止别人拆笼子**。
拆笼子需要的权限是"本机管理员"，跟网络状态无关。

## 5. 诊断：确认到底装了什么

```powershell
# 列出所有 WFP 过滤器（输出很长，重定向到文件看）
netsh wfp show filters > C:\wfp-filters.txt

# 只看我们装的（会话名带 aegis- 前缀）
Select-String -Path C:\wfp-filters.txt -Pattern "aegis-" -Context 0,6
```

`aegisd` 起的会话名形如 `aegis-cage-<毫秒时间戳>`，探针起的形如
`aegis-probe-<毫秒时间戳>`。搜 `aegis-` 就能找到。

过滤器名字是中文（`回环放行` / `DHCP 放行·服务端67` / `默认拒绝` / …），
在 `netsh` 输出里可以直接认出来。

## 6. 事后复盘

拆除之后请保留这些再重启/继续：

1. **审计日志**：`.aegis-run/audit-*.binlog`，哈希链，记录本次启动的事件；
2. **守护进程输出**：`aegisd` 的 stdout，里面有每一步的裁决依据和
   下发/撤销的实际条数；
3. **`netsh wfp show filters` 的转储**（见 §5）。

最需要回答的两个问题：

- **是哪条规则把正常流量挡了？** 对照 §5 的转储和 `aegisd` 打印的计划；
- **为什么它会挡住？** 多半是角色裁决错了（把校园网卡判成了绝缘），
  而不是规则本身写错——先看 `aegisd` 第 4 步"角色裁决"的输出。

## 7. 预防：别让自己走到这一步

- **下发前先跑两个无害探针**：
  - `cargo run -p aegis-wfp --example apply_probe`
    把计划里所有**放行类**规则逐条"装上再拆掉"。放行规则装上去等于什么都没变，
    但它能验证翻译层对不对。
  - `cargo run -p aegis-wfp --example block_probe`
    解析百度拿到真实 IP，装一条**只拦"这个 IP 的 443"**的规则，自己做前后
    对照：443 断、80 仍通、拆掉后恢复。只拦一个网站几秒钟，
    却把"阻断规则真的生效"从信念变成实测结果。

  这两个探针的存在理由：WFP **没有** dry-run 接口，`FwpmFilterAdd0`
  要么成功要么报错，没有"试算一下不下发"。而真机实测已经靠它们抓出了两个
  只有真跑才会暴露的错（条件类型不匹配、地址字段这一层不支持）。
- **别跳过 10 秒倒计时**。`aegisctl apply` 之后不 `confirm`，
  规则会在 10 秒后自动撤销——这是给你的观察窗口，不是流程负担。
- **改计划之前先看 `preflight` 拒绝什么**。Boot 规则、无法精确映射的条件，
  都会在碰引擎之前被拒绝。
