# Windows 服务宿主

让 `aegisd` 作为服务常驻、开机自启动。

> ⚠ **本文档里的每条命令都会改这台机器的状态。**
> `install` 尤其——它让一个 **SYSTEM 权限**的进程在你每次开机时自动起来。
> 执行前请确认你知道自己装的是什么（§2 有一句话版本）。

---

## 1. 为什么要服务

`aegisd` 目前必须手动跑（`cargo run -p aegisd -- ...`），这意味着每次重启电脑
都要记得先开一个终端。对一个"兜底型安全工具"来说这不可接受——它的价值恰恰是
**你忘了它也在**。

服务形态还顺带解决了权限问题：守护进程需要管理员（§16），而服务由 SCM
以 SYSTEM 身份拉起，不需要你每次手动提权。

---

## 2. 一句话版本

```bash
# 以管理员身份打开 PowerShell 或终端，然后：
aegisd install --config config/config.example.toml --start
```

装完之后 Aegis 开机自启，`aegisctl` 随时能连上。

⚠ 三件要知道的事：

1. 它注册的服务是 **Aegis**（显示名"Aegis 守护进程"），启动类型**开机自启**。
2. 停止服务 = 进程退出 = **WFP 动态会话里的规则全部清空**，网络立刻恢复。
   这是设计好的兜底，不是故障。
3. **UAC 自动提权没做**——请自己开管理员终端。

---

## 3. 命令

| 命令 | 需要管理员 | 作用 |
|---|---|---|
| `aegisd status` | 否 | 查服务是否已安装 |
| `aegisd install --config <路径> [--data-dir <目录>] [--start] [--start-type auto\|demand]` | **是** | 注册服务 |
| `aegisd uninstall` | **是** | 删除服务 |
| `aegisd start` | **是** | 启动 |
| `aegisd stop` | **是** | 停止 |
| `aegisd --service`（不是子命令，是 flag） | — | SCM 拉起时的入口。**不要手工跑**：它会阻塞等 SCM 调度，手工跑只会立刻报错退出 |

`install` 记录的是**当前这个 exe 的路径**。所以先用完整路径跑 install，
或者先把 `aegisd.exe` 放到固定位置再装。

`--data-dir` 默认 `.aegis-run`（相对路径）。作为服务跑时，相对路径是相对
**系统目录**（`C:\Windows\System32`）解析的——不是你想的那样。装之前务必给绝对路径：

```bash
aegisd install --config C:\ProgramData\Aegis\config.toml --data-dir C:\ProgramData\Aegis --start
```

## 4. 三条设计取舍

### 4.1 服务外壳与守护链路共用一份实现

服务模式只是"起一个线程跑 `serve()`，主线程交给 SCM"。链路逻辑只有一份
（`main.rs` 的 `serve()`）。

⚠ 绝不允许出现"服务版链路"和"控制台版链路"两份实现。它们迟早漂移，
而漂移方向通常是服务那份少了某个 Fail-Closed 分支——那意味着**平时有保护、
开机后没保护**。

### 4.2 停止时不做优雅停机

收到 SCM 停止信号 → 直接结束进程。看着像偷懒，其实是刻意的：

- 所有 WFP 规则都在**动态会话**里，进程一死内核立即清空
  → "忘了收尾"与"立即收尾"在这里是**同一个结果**
- 反过来若为优雅而主动 `force_teardown()`，反而多出一段
  "进程还活着但规则已撤"的窗口期，那才是真正的风险

### 4.3 `--serve-secs` 在服务模式下被忽略

控制台默认等 30 秒（给演练用）。服务要是照抄这个默认值，开机 30 秒后自己就没了——
现象是"服务看起来在、但连接不上"，排错方向会跑到 IPC 上去。

代码里显式忽略它，并在启动日志里说明"被忽略是刻意的"。

## 5. 排障

| 现象 | 先查什么 |
|---|---|
| `status` 说没装，但你想确认 | 正常：用管理员终端查 `sc query Aegis` |
| 服务启动了但 `aegisctl` 连不上 | ① token 路径：服务用的是 `install` 时记的绝对路径，不是你 shell 里的相对路径；② 管道名：服务参数里的 `--pipe` 优先于默认值 |
| 服务刚启动就停 | 看事件查看器 → Windows 日志 → 应用程序。**最常见原因是配置读不到**——服务以 SYSTEM 身份跑，`--config` 里的相对路径会解析到 `C:\Windows\System32` |
| 停止后网络没有恢复 | 这是**不应该**发生的现象。动态会话在进程退出时必然清空。若真发生，说明装的是别的服务或用了持久过滤器（见 `docs/PERSISTENT-CAGE.md`），先 `aegisctl rollback` |
| 想临时回到手动跑 | `aegisd stop`。守护进程链路和控制台完全一样，不用重装 |

---

## 6. 还没做的

- **UAC 自动提权**：现在需要人自己开管理员终端。这是有意的取舍——见 §9 阶段 0 的注释。
- **服务恢复策略**（崩溃后自动重启 / 失败重试）：`SERVICE_FAILURE_ACTIONS` 没配。
  当前行为：服务挂了就是挂了，需要手动 `aegisd start`。
- **事件日志输出**：守护进程只往 stdout 打印，而服务上下文里 stdout 没人接。
  排障只能靠事件查看器里的 SCM 报错。
- **依赖声明**：没声明依赖其它服务（`lpDependencies` 传空）。如果将来它需要
  依赖 RPC 之类的服务，那时要补。

以上四条都是"能用但不够完善"，不影响本模块的核心承诺。
